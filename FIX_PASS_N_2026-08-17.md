## 5.1 Part A — UUID/VARCHAR audit bind

### Root cause

Column type is VARCHAR. Callers still pass UUID objects.

Migration order:

1. `002_block_n_admin` created `audit_logs.tenant_id` as UUID.
2. Uncommitted `004_tenant_id_varchar` (and the matching working-tree model) changed `audit_logs.tenant_id` and `tool_policies.tenant_id` to `VARCHAR(255)` to match Block D’s canonical tenant id.
3. `users.tenant_id` and `tenant_connectors.tenant_id` are still UUID.

`write_audit_log` was typed `tenant_id: UUID` and assigned that object onto `AuditLog.tenant_id`. Every admin route does `_as_uuid(str(tenant.tenant_id))` (or `UUID(...)` in sessions) before calling it. asyncpg then failed: `expected str, got UUID`.

Same bind on the **read** path: `GET /api/v1/admin/audit` compared `AuditLog.tenant_id == UUID(...)`. N2 would have hit that even after inserts worked.

MCP’s `write_mcp_audit` already passed `tenant_id: str`. Block N was the inconsistent side.

### Fix (attempt 1 of 3)

`.bak` then:

- `backend/app/services/admin/audit_logger.py` — accept `UUID | str`, persist `str(tenant_id)`.
- `backend/app/api/v1/admin/audit.py` — filter with `str(UUID(str(tenant.tenant_id)))` so the list query binds a string.

Admin mutation routes still pass UUID into `write_audit_log`; the logger is the coercion boundary. `users` / connector UUID comparisons were left alone (those columns are still UUID).

### Probe (real Postgres, before rewriting tests)

```
write_ok True
stored_tenant_id_type str
stored_tenant_id_equals_str True
stored_action part_a.probe
```

Single `write_audit_log(..., tenant_id=<uuid4()>)` against `block_n_verify` committed and read back as `str`. Stopped at 1 attempt.
